# trivy — software-composition analysis (T1593.003, Analysis)

Find known-vulnerable dependencies (by CVE) in the lockfiles and installed packages of source you
obtained during the engagement — a broad-ecosystem alternative to grype. Passive tier — allow-listing
T1593.003 in the ROE is enough; no authoriser needed. The target is a workspace-relative path written
`src:<dir>`, mounted read-only at `/src`. The first run downloads trivy's vulnerability database.

Run — point it at the source directory inside the engagement workspace:

    searu run trivy --technique T1593.003 --target src:loot/acme-src

The wrapper runs the vulnerability scanner only (secrets and misconfig are other tools). Add trivy's own
flags after `--` (e.g. `-- --severity CRITICAL,HIGH`). Read results:

    searu findings --tool trivy

Each finding is one vulnerable package, titled by the CVE id, evidence the `package@version`, tagged
with the CVE's CWE(s); severity is trivy's. Confirm the flagged version is the one actually deployed,
then a reachable, exploitable CVE promotes to an exploitation run with an authoriser. Do not paste raw
trivy output. See `searu tool advice trivy` for detail.
