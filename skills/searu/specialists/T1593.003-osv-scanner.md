# osv-scanner — software-composition analysis (T1593.003, Analysis)

Match the lockfiles of source you obtained during the engagement against Google's OSV database of known
vulnerabilities — a complement to grype and trivy. Passive tier — allow-listing T1593.003 in the ROE is
enough; no authoriser needed. The target is a workspace-relative path written `src:<dir>`, mounted
read-only at `/src`.

Run — point it at the source directory inside the engagement workspace:

    searu run osv-scanner --technique T1593.003 --target src:loot/acme-src

Add osv-scanner's own flags after `--`. Read results:

    searu findings --tool osv-scanner

Each finding is one vulnerable package, titled by the CVE (or the OSV id when there is no CVE), evidence
the `package@version`. Severity is not normalised here — confirm it from the CVE, then a reachable,
exploitable one promotes to an exploitation run with an authoriser. Do not paste raw osv-scanner output.
See `searu tool advice osv-scanner` for detail.
