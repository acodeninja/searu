# gitleaks — secret scanning (T1593.003, Analysis)

Sweep a source tree you obtained during the engagement for hardcoded credentials, API keys and tokens.
Passive tier — allow-listing T1593.003 in the ROE is enough; no authoriser needed. The target is a
workspace-relative path written `src:<dir>`, mounted read-only at `/src`.

Run — point it at the source directory inside the engagement workspace:

    searu run gitleaks --technique T1593.003 --target src:loot/acme-src

Add gitleaks' own flags after `--` (e.g. `-- --config custom.toml` for a tuned ruleset). Read results:

    searu findings --tool gitleaks

Each finding is one leak (CWE-798), titled by the gitleaks rule id, evidence `file:line`; the secret
value itself is not stored — open the file to read it. Treat each as a candidate credential: verify it
out of band, and a live one authorises a credential-access run within the ROE. Do not paste raw
gitleaks output. See `searu tool advice gitleaks` for detail.
