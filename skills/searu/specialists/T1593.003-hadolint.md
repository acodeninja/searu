# hadolint — Dockerfile linting (T1593.003, Analysis)

Check the Dockerfile in source you obtained during the engagement for insecure and fragile build
practices — unpinned base images, unverified downloads, running as root. Passive tier — allow-listing
T1593.003 in the ROE is enough; no authoriser needed. The target is a workspace-relative path written
`src:<dir>`, mounted read-only at `/src`; hadolint lints `<dir>/Dockerfile`.

Run — point it at the directory containing the Dockerfile:

    searu run hadolint --technique T1593.003 --target src:loot/acme-src

Add hadolint's own flags after `--` (e.g. `-- --ignore DL3008`). Read results:

    searu findings --tool hadolint

Each finding is one rule hit, titled by the rule code (DLxxxx / SCxxxx), evidence `file:line`; hadolint
does not attach a CWE. Severity maps error/warning/info/style. An unpinned base or an unverified
download is a supply-chain foothold to note; feed a running-as-root or exposed-secret finding into the
broader attack picture. Do not paste raw hadolint output. See `searu tool advice hadolint` for detail.
