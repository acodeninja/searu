# semgrep — static application security testing (T1593.003, Analysis)

Scan a source tree you obtained during the engagement (dumped via a traversal, cloned from an exposed
`.git`, or otherwise retrieved) for injection, unsafe APIs, hardcoded secrets and other weakness
patterns. Passive tier — allow-listing T1593.003 in the ROE is enough; no authoriser needed. The
target is a workspace-relative path written `src:<dir>`, mounted read-only at `/src`.

Run — point it at the source directory inside the engagement workspace:

    searu run semgrep --technique T1593.003 --target src:loot/acme-src

Override the default `auto` ruleset with semgrep's own flags after `--` (e.g. `-- --config p/python`).
Read the results:

    searu findings --tool semgrep

Each finding is one rule hit, titled by the semgrep rule id, evidence `file:line`, tagged with the
rule's CWE(s); severity maps ERROR→high, WARNING→medium. All are static and need review — triage each
against the running app. A confirmed injection point promotes to an exploitation run (sqlmap/commix)
with an authoriser. Do not paste raw semgrep output. See `searu tool advice semgrep` for detail.
