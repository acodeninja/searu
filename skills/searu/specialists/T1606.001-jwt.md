# jwt — forge a JSON Web Token (T1606.001, CWE-347)

Forge a token the app will trust: an unsigned `alg:none` token, or a key-confusion (RS256→HS256) token
signed with the server's public key. Exploitation tier — the ROE must allow-list T1606.001 and name an
authoriser. Take the victim token from `searu loot --reveal` (a login, whoami, or SQLi yields it).

Run (the target is the in-scope URL the token belongs to; the token and flags follow `--`):

    searu run jwt --technique T1606.001 --target http://host:port -- <JWT> -X a -b     # forge alg:none, bare
    searu run jwt --technique T1606.001 --target http://host:port -- <JWT> -X k -pk public.pem -b   # key confusion

Read results:

    searu loot --reveal            # forged tokens (category forged-jwt)
    searu findings --tool jwt      # a CWE-347 signature-verification finding (needs-review until replayed)

The finding is needs-review: jwt_tool only *forges* the token. Confirm it by replaying the forged token
as `Authorization: Bearer <token>` against an authenticated endpoint — tamper a claim first (e.g. set
`role` to `admin`) to prove the bypass. Don't paste raw jwt_tool output. See `searu tool advice jwt`.
